# v1.0.0 Release Notes

## Release Name

GPU Benchmark Lab v1.0.0 - Public Launch Candidate

## Summary

This release prepares GPU Benchmark Lab for public GitHub publication as a professional AI infrastructure engineering portfolio repository.

The central story is:

> Engineering an Enterprise GPU Benchmarking and Validation Environment.

## What Changed

### Documentation

- Improved README for first-time visitors with badges, audience-specific navigation, launch status, and validation instructions.
- Added public repository configuration variables in `_config.yml`.
- Added publication configuration documentation.
- Added GitHub Discussions guide.
- Added Security policy and CODEOWNERS.
- Added professional release index in `RELEASES.md`.

### Reports and PDFs

- Regenerated every report PDF from the latest Markdown source.
- Added a reproducible PDF generation script.
- Added PDF validation coverage to the documentation validation workflow.

### GitHub Readiness

- Added GitHub Issue templates for bug reports, documentation improvements, questions, and enhancements.
- Added Pull Request template.
- Added GitHub Actions for Markdown validation, Mermaid validation, and link validation.
- Added markdownlint configuration.
- Improved `.gitignore` for local environments and generated validation artifacts.

### Public-Safe Positioning

- Continued explicit separation between public methodology and proprietary GPUValidator software.
- Preserved the policy against publishing implementation details, production screenshots, private URLs, secrets, customer identifiers, or unsupported benchmark metrics.

## Validation

Validated locally for LC1:

- Markdown, links, image references, Mermaid fences, headings, sensitive text patterns.
- Mermaid render checks.
- PDF regeneration and text extraction checks.
- GitHub Pages local browser compatibility.

## Known Limitations

- Additional benchmark families should be added only when approved raw evidence is available.
- Topology evidence remains methodology-only until a sanitized topology artifact is approved.
- Public contact destinations are configured in `_config.yml` and should be updated before publication if desired.

## Upgrade / Publication Notes

Before making the repository public:

1. Confirm `_config.yml` values match the final repository owner, Pages URL, and public contact choices.
2. Enable GitHub Pages from the repository root or the intended Pages source.
3. Enable GitHub Discussions if the public community workflow is desired.
4. Push the `v1.0.0` tag and create a GitHub Release using these notes.
